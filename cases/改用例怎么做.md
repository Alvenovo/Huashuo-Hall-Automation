# 改用例怎么做

> **一句话：改用例 = 改 `cases/cases.yaml` 一个文件。** 99% 的情况到此为止。
>   
> 设计背景见根目录《用例数据化方案.md》。

---

## 三种操作

```powershell
# ① 改一条：直接编辑 cases/cases.yaml（名字 / 验证点 / 优先级 / 上下线 / 期望值 / 参数）
# ② 加一条：也是编辑 cases/cases.yaml，追加一个条目
# ③ 删一条：把那个条目删掉

# 改完跑这三步（少一步守卫会红，它会告诉你漏了哪步）
.venv\Scripts\python.exe -X utf8 tools\cases_export.py --format md
.venv\Scripts\python.exe -X utf8 -m pytest tests/unit/test_cases_inventory.py -m unit -q
.venv\Scripts\python.exe -X utf8 -m pytest tests/unit -m unit -q
```

**改完不用碰任何 `.py`。** 已实测：往 `cases.yaml` 加一条用例，收集数 `44 → 45`，
  
改动前后 `.py` 文件清单**完全一致**，脚本自动把它挂到了对应的通用用例函数上。

## 加一条用例长什么样 

```yaml
- id: P1C-01b                                  # 编号，唯一
  title: 注册页不该出现「邀请码」输入框            # 用例名
  suite: login                                 # 套件（见 hall_auto/suites.py）
  marker: [login]                              # pytest 标记
  tier: data                                   # data = 数据驱动
  kind: case
  status: active
  driver: controls_present                     # 用哪个模板
  page: register                               # 哪个页面
  expect: [phone]                              # 必须有的控件
  expect_absent: [invite]                      # 必须没有的控件
  verify: 注册页上只有既有那些控件；哪天产品加了「邀请码」输入框，这条会红
  needs: 无需凭据（用假号假码）
```

**就这样，不用写 Python。** 只要 `page` 是已经登记过的页面，脚本自己把它挂上去。

### 现成的模板和页面

```powershell
.venv\Scripts\python.exe -X utf8 tools\run_cases.py --list-drivers
```

| 模板                        | 断言什么              | 给什么                                                   |
| ------------------------- | ----------------- | ----------------------------------------------------- |
| `controls_present`        | 页面上列出的控件都在        | `page` + `expect`（+ `expect_absent` / `expect_exact`） |
| `radio_group_exactly_one` | 一组档位都在、**恰有一个**选中 | `page` + `group`（+ `expect_exact`）                    |

## 什么情况才真的要动代码

| 你想做的                              | 改哪里                                                   |
| --------------------------------- | ----------------------------------------------------- |
| 换用例名 / 验证点 / 优先级 / 上下线 / 参数 / 期望值 | **`cases/cases.yaml`**                                |
| 加一条**同页面、同一种断言**的用例               | **`cases/cases.yaml`**                                |
| 加一个**新页面**的用例                     | Python：`hall_auto/drivers.py` 的 `PAGES` 加一行 + 一个薄测试函数 |
| 加一种**新断言**                        | Python：`drivers.py` 加一个模板                             |
| 换成哪个 app / 用哪个关键词 / 钉哪个版本         | **`config.yaml` / `config.local.yaml`**               |

**判据一句话**：「**断言什么**」可以数据化；「**打开哪个页面、怎么走到那一步**」不行。

## 「脚本自动维护」是怎么保证的

守卫 `tests/unit/test_cases_inventory.py` 每次跑单测都检查：

1. 用例文件 schema 合法（必填字段、枚举值、编号唯一）
2. 有 `ref` 的 → 那个函数必须存在
3. 没 `ref` 的 → `driver` + `page` 必须能解析出通用函数（否则**永远跑不到**）
4. 代码里每个 `def test_` 都要么被 `ref` 指着、要么是通用用例函数
5. `cases/清单.md` 与真源一致（**忘了重出就红**）

**所以「自动维护」不靠人记得** —— 改了用例忘了重出清单、加了用例没挂上、删了函数没删条目，
  
**守卫都会红并告诉你哪一条**。

## 附录：少数情况 —— 换一个被操作的 app

（**少数**情况，所以放最后。绝大多数改用例就是上面那些。）

「把夹具应用从网易云音乐换成 QQ 音乐」看着像改用例，其实**不该改用例文件** ——
  
用例里写的是「夹具真装真卸」，一个字都没提网易云。

**要改的是配置**（`cases.yaml` 不用动）：

1. `config.local.yaml` 的 `fixture_apps.install` / `.uninstall` → 写商店里的条目名
2. `config.yaml` 的 `fixture_profiles` 补一条：
   ```yaml
   "QQ音乐":
     process_names: ["QQMusic"]   # 装之前要先收掉的进程映像名
     cta_min_area: 12000          # 自绘主按钮的最小面积（只允许比默认 12000 小）
   ```

唯一必须**实测**的是「商店条目名」和「主按钮面积」—— 那两个数据不实测就是猜。

⚠️ `cta_min_area` **只允许往低调**：调高会让自绘主按钮过不了第一道，
  
退到兜底链第三道点到「关闭(\&L)」，等于把安装器关掉。所以代码里做了拒绝（退回默认）。

**真的做不到的**：新 app 的**安装流程本身**不一样（NSIS → MSI、商店内安装、网页安装）——
  
那不是参数，是**新的交互**，必须写代码。
