# 改用例怎么做（含实例：把夹具从网易云音乐换成 QQ 音乐）

> 面向：以后要改用例的人。**先看第一节的判据，再看实例。**
> 设计背景见根目录《用例数据化方案.md》。

---

## 一、判据：先问「这个改动属于哪一层」

| 层 | 内容 | 改哪里 | 例子 |
| --- | --- | --- | --- |
| **数据层** | 编号 / 用例名 / 验证点 / 优先级 / 上下线 / 参数 / **换成哪个 app** | `cases/cases.yaml` 或 `config.yaml` | 「夹具应用从 A 换成 B」 |
| **交互层** | 打开哪个页面、点什么按钮、**怎么认出那个按钮**、怎么定位控件 | **Python**（`hall_auto/*.py`） | 「B 的安装按钮是自绘的、要按面积认」 |
| **断言层** | 断言什么、期望值 | `cases/cases.yaml` 的 `verify` + 少量代码 | 「原来断言注册表有条目，现在改成断言 X」 |

**一句话**：**「换成哪个」是数据；「怎么点、怎么认」是交互；「断言什么」是用例。**

⚠️ **最容易搞混的一点**：很多改动**根本不该落在用例文件里**。
下面这个实例就是 —— 「换夹具应用」落在 `config.local.yaml` 和代码里，**用例文件一个字都不用动**。

## 二、实例：夹具从「网易云音乐」换成「QQ 音乐」

> 下表里的行号是 **2026-10-13 的快照，会随代码变动** —— 找不到就按**符号名**搜。

### 先看现状（2026-10-13 实查）

| 位置 | 现在的值 |
| --- | --- |
| `config.local.yaml` → `fixture_apps.install` / `.uninstall` | `网易云音乐` |
| `config.yaml` → `fixture_apps`（committed，机器无关） | 全空 |
| `config.yaml` → `update_fixture`（大厅内更新那条） | **7-Zip（64位）26.02** —— 跟 install/uninstall 是**两回事** |
| `tools/bootstrap_machine.py:1450-1452` | 新机铺环境时写的默认值也是 `网易云音乐` / `7-Zip（64位）` |
| `cases/cases.yaml` 的 P1A-02 / P1A-03 | **一个字都没提「网易云」** —— 写的是「夹具真装真卸」 |

### ⚠️ 为什么不是「改个配置就完事」

`hall_auto/apps.py` 里有 **4 处「网易云专属」的假设**，换 app 时必须逐个核对：

| # | 位置 | 假设 | 换 app 会怎样 |
| --- | --- | --- | --- |
| 1 | `apps.py` 的 `FIXTURE_PROC_HINTS`（2026-10-13 在 626 行） | 网易云跑起来的进程映像是 `cloudmusic` | **不登记新 app → 装之前不会先收进程** → 撞 NSIS「不能打开要写入的文件」模态框，无人值守**干等到超时**（2026-09-29 真踩过） |
| 2 | `apps.py` 的 `CTA_MIN_AREA = 12000`（在 363 行） | 自绘「立即安装」按钮 **360×60=21600**，所以门槛定 12000 | 新 app 的主按钮**面积小于 12000 就认不出来**（点不动，报「找不到安装按钮」） |
| 3 | `apps.py` 的 `pick_wizard_button`（在 461 行） | 网易云的**卸载页**把真按钮画成两块同样大的自绘块，所以改走「按文字点隐藏的 NSIS 按钮」 | 新 app 的卸载器不是这个套路时，这段要么不适用、要么要改 |
| 4 | `apps.py` 的 `match_display_name` 那段（在 675 行附近） | 商店里那条叫「**网易云音乐官方版**」，所以用 `match_display_name` 模糊匹配 | 新 app 的商店条目名要实测（可能带「官方版」这类后缀），否则报「商店里搜不到夹具应用」 |

### 操作步骤

**第 0 步：先实测 QQ 音乐**（这步不能省 —— 上面 4 处都要按它核对）

| 要测什么 | 怎么测 | 用来填哪 |
| --- | --- | --- |
| 商店里的**条目全名** | 大厅搜「QQ音乐」，看结果列表 | 第 4 处（`fixture_apps` 该写哪个名字） |
| 详情页**主按钮的文字和面积** | `tools/probe_uia.py` 看 UIA 树 | 第 2 处（面积门槛够不够） |
| 装完后的**进程映像名** | 任务管理器 / `tools/probe_win32.py` | 第 1 处（`FIXTURE_PROC_HINTS`） |
| **卸载页**长什么样 | 手动走一遍卸载，看按钮是自绘还是标准 NSIS | 第 3 处 |

**第 1 步：改 `config.local.yaml`（每台机器都要改）**

```yaml
fixture_apps:
  install: QQ音乐        # ← 写商店里那个条目名（第 0 步测出来的）
  update: 7-Zip（64位）   # 不动：这是「大厅内更新」那条用的，另一回事
  uninstall: QQ音乐
  sync: ""
```

**第 2 步：按实测结果改 `hall_auto/apps.py`**

- **必改**：往 `FIXTURE_PROC_HINTS` 加一行
  ```python
  FIXTURE_PROC_HINTS = {
      "网易云音乐": ("cloudmusic",),
      "QQ音乐": ("QQMusic",),        # ← 进程名以第 0 步实测为准
  }
  ```
- **可能要改**：`CTA_MIN_AREA`（实测面积小于 12000 就调低）、`pick_wizard_button` 的卸载页分支。

**第 3 步：改 bootstrap 的默认值**（`tools/bootstrap_machine.py:1450-1452`）
否则**以后新铺的机器还是网易云**，只有你手改过的那台是 QQ 音乐。

**第 4 步：验证**（提权终端，会真装真卸）

```powershell
$env:HALL_ALLOW_INSTALL = "1"
.venv\Scripts\python.exe -X utf8 -m pytest tests/launch/test_p1_apps.py -m "apps and destructive" -v
```

**第 5 步：用例文件** —— **不用动**。
如果想留痕，可以在 `cases/cases.yaml` 的 P1A-02 / P1A-03 的 `needs` 里写一句
「夹具应用见 `config.local.yaml` 的 `fixture_apps`」—— 可选。

## 三、那什么情况才真的要改用例文件

| 想做的事 | 改哪里 |
| --- | --- |
| 改用例名 / 验证点 / 优先级 / 上下线 | **`cases/cases.yaml`** |
| 给参数化用例加一组参数 | **`cases/cases.yaml`** |
| 改控件图用例的期望控件 | **`cases/cases.yaml`** |
| 加一条**同类型**用例（同页面、同一种断言） | **`cases/cases.yaml`** |
| 换成哪个 app / 用哪个关键词 / 钉哪个版本 | **`config.yaml` / `config.local.yaml`** |
| 加一条**新页面 / 新交互**的用例 | **Python**（`hall_auto/` + 一个薄测试函数） |
| 改「怎么认出按钮 / 怎么定位控件」 | **Python**（`hall_auto/apps.py` 那类） |

**改完 `cases.yaml` 必做三步**（否则守卫会红）：

```powershell
.venv\Scripts\python.exe -X utf8 tools\cases_export.py --format md
.venv\Scripts\python.exe -X utf8 -m pytest tests/unit/test_cases_inventory.py -m unit -q
.venv\Scripts\python.exe -X utf8 -m pytest tests/unit -m unit -q
```

## 四、这个实例说明了什么（**别抱错期待**）

「换成哪个 app」确实是数据，但**真正的难点不在这** —— 难点是「新 app 的按钮长什么样、怎么认」，
那是交互层，**永远要写代码**。这就是 UI 自动化的物理边界。

**所以数据化的收益是**：清单、编号、验证点、参数、期望值不用碰代码。
**不是**：换一个 app 完全不用写代码。

**如果希望「换 app」也变成纯配置**，可以再做一步重构：把上面那 4 处假设抽成
`config.yaml` 里的一张 **app-profile 表**（进程名 / 主按钮面积门槛 / 商店名后缀 / 卸载器类型）。
那是一块**独立的、能验证的**重构（现有行为 1:1 保留，用单测钉住），
但**需要第 0 步的实测数据才能填新 app 那一行**。要做的话单独说。
